Glossary · Retrieval and models

What is Re-ranking?

Re-ranking is the second stage of retrieval in which an initial set of candidate passages is re-scored by a stronger, more expensive model so that only the most query-relevant passages reach the generation step.

In short: A second pass that re-scores retrieved passages for relevance.

Why it matters

Retrieval usually has two competing goals: recall in the first pass and precision in the second. A page can be fetched as a candidate and then dropped, because another passage scored higher on the specific question. This is the most common reason a brand claims 'we rank, but we are never quoted'.

How to work with it

Write each passage so its relevance to one question is obvious: a descriptive heading, the answer in the first sentence, and no competing topics in the same paragraph.

Common mistakes

  • Assuming that being retrieved as a candidate is the same as being used.
  • Burying the passage that answers the query under unrelated background.
  • Writing headings that describe the section vaguely, so the re-scorer cannot match it to the question.

FAQ

How is re-ranking different from ranking?

Ranking orders documents for a results page. Re-ranking orders retrieved passages for a model's context window, using a different objective: maximum answer usefulness, not maximum click likelihood.

Can I optimise for re-ranking specifically?

Indirectly, by making every section sharply relevant to one question. Passages that mix several topics score weakly because the model cannot tell which part answers the query.
