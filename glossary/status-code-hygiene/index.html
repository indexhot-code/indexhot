What is Status Code Hygiene?

Last updated November 2026 · Reviewed against the IndexHot GEO Measurement Standard v1.0

Status code hygiene is the discipline of returning the status that describes reality. A missing page returns 404 or 410, a moved page returns 301 to its replacement, and a working page returns 200. Anything else teaches crawlers that the site's signals are unreliable.

In short: Whether the site returns the correct HTTP status for every kind of URL: 200, 301, 404 or 410.

Why it matters

The failure is usually soft 404: a missing URL returning 200 with a template or the homepage. Crawlers record it as a valid page, index nothing useful, and repeat the fetch next cycle.

On a growing site this compounds. Every renamed article, every broken inbound link and every mistyped URL become a fetch that returns a page with no unique content, and the share of wasted crawl rises until it is the majority.

How to work with it

Test the four cases explicitly and verify the response, not the rendering.

  • Unknown path returns 404 with a page that says so.
  • Bare directory path returns 301 to the trailing-slash version, not 200 or 404.
  • Retired pages return 410 or 301 deliberately, never 200 with a placeholder.

Common mistakes

  • Serving the homepage for unknown paths, the classic soft 404.
  • Returning 200 for a directory path and a second 200 for its slash version, splitting signals between duplicates.
  • Changing the status policy without re-testing; redirect rules are easy to break and silent when broken.

FAQ

How do I check quickly?

Fetch a handful of known-bad paths with curl and read the status line. Four requests cover the four cases.

Does it matter for a small site?

Yes, because the cost is relative. On a 140-page site, fifty soft 404s is a third of the crawlable set.
