Technical Readiness for AI Search: Twelve Checks That Decide Retrieval

By IndexHot Team · November 27, 2026 · 11 sections

A brand missing from AI answers can be missing for three unrelated reasons, and only two of them are technical. This guide covers the two: whether a retrieval system can fetch your page at all, and whether the document it fetches is the one you wrote. Twelve checks, each finishable in an afternoon, each cheaper than the content work people usually start with instead.

Technical readiness is a third, separate thing

Three different failures look identical in a report: the brand is not mentioned. It can be missing because the page cannot be fetched, because the page can be fetched but not indexed, or because the page is indexed and simply not chosen. Only the first two are technical, and both must be cleared before any content work has a chance to show up.

The reason this deserves its own guide is that the checks are cheap, objective and finishable. Content work is neither. A team that spends a quarter writing before verifying access spends it against an unknown denominator, and then argues about whether the writing was good.

Order of operations: verify access per page, verify indexation per page, verify the fetched document is the one you wrote, and only then look at whether the content deserved to be quoted. Doing this in reverse is the most common way to waste six months.

Gate one: can it be fetched at all

Retrieval starts with a request. If that request is refused, nothing downstream exists. Three things refuse requests, and they are checked in this order: robots rules, edge protection, and the server itself.

User agents are not one thing

Every major answer engine operates more than one crawler, and they do different jobs. Blocking a training crawler removes your pages from model training; blocking the retrieval crawler removes your pages from answers. These are separate switches, and sites routinely flip the wrong one while believing they have made a privacy decision.

Edge protection that refuses politely

A web application firewall configured to challenge unfamiliar clients will challenge a retrieval bot too. The rules are usually written for scrapers, and a bot that identifies honestly gets caught by them. Check the raw response for a 403 or a challenge page, not just whether the browser renders.

Cloudflare, Akamai and Fastly all publish their own bot-management behaviour, and all three will let you allowlist a named agent. The check is not whether you have a firewall; it is whether the ten pages that matter return 200 to the retrieval user agent.

Gate two: indexed where it matters

Index membership is per index, not global. A page can be comfortably indexed in Google and entirely absent from the index that grounds Copilot, which runs through Bing. This is a real and frequently missed condition, and it produces the most misleading kind of absence: rankable in one product, invisible in another.

  • Submit and verify per engine rather than assuming one sitemap covers everything.
  • Check whether the sitemap is actually discovered: look for fetches of it in the server log.
  • For Bing, prefer IndexNow so changes are pushed instead of waited for.
  • For Google, use URL Inspection per page when the page matters; sitemap status alone will not tell you individual pages are in.

There is a second, subtler form of absence: the page is indexed under a different URL than the one you promoted. Parameter variants, trailing-slash variants and http/https variants all create duplicates, and answers may cite the variant your analytics does not track. Canonical tags do not merge indexes; they only express preference, and preference is sometimes ignored.

Gate three: does the fetch return your document

This is the check almost nobody runs, and it is the one that most often explains a mystery. Fetch the URL the way a bot does, with no cookies and no JavaScript execution, and compare the bytes to what you think you published.

Status codes carry meaning you did not intend

A soft 404, where a missing page returns 200 with an apology page, teaches a crawler that your site contains large amounts of near-duplicate content. It also means the deletion you thought you made never happened. Status hygiene is not housekeeping; it is a statement about which URLs are real.

ResponseWhat a retrieval pipeline does with it
200 with the real page
Uses the document. This is the only outcome you want.

Two further traps sit here: an interstitial that renders before content, and a canonical that points somewhere else. The first means the fetched document has no substance even when the status is 200. The second means you asked the index to prefer a different URL, and it may comply.

Rendering: what the client side hides

Retrieval pipelines operate under latency budgets. Rendering a JavaScript application costs seconds and a browser; fetching static HTML costs milliseconds. Faced with that difference, most pipelines take the cheap path and read what the server returned.

This does not make JavaScript sites unreadable. It makes them conditionally readable: readable if the renderer runs, if it succeeds, if it is not skipped for budget reasons. Conditional readability is a bad foundation for a page you want quoted.

  • Ship the answer in the initial HTML, then let the client add interaction on top.
  • Do not put prices, specifications, availability or dates exclusively in a client-rendered component.
  • Test with JavaScript disabled and read what remains; that is closer to what a cheap fetch sees.
  • If you must render, server-side render the content routes and hydrate afterwards.

One diagnostic is unusually informative: open the page with JavaScript disabled, find the paragraph you most want quoted, and see whether it is there. If it is not, no amount of copy editing will help, and the fix belongs with whoever owns the front end.

Structure inside the document

Once the document is fetchable and faithful, the next question is whether a passage inside it can stand alone. Retrieval works on chunks, and a chunk is only useful if its meaning survives being cut out of the page.

That gives a concrete editorial rule: every section should begin with a sentence that states its claim without pronouns pointing backwards. This sentence, and the two or three after it, is what gets lifted. If it begins with as noted above, the lifted text means nothing.

  • One subject per heading, and the heading names that subject rather than the campaign.
  • Sections that answer a whole question, not a fragment of a narrative that spans the page.
  • Lists and tables where the content has parts, because they survive extraction intact.
  • No critical facts in images, and no critical facts only in captions.

The ceiling here is set by the page, not the paragraph. A page of forty short sections answering forty questions is easier to retrieve from than a page of four long essays, because the retrieval unit that matches a query is smaller and better aligned. That is why question-shaped architecture outperforms topic-shaped architecture on these surfaces while both remain fine for classic search.

Structured data: what it does and does not do

Schema markup helps machines resolve entities and relationships. It does not make a weak passage quotable, and it does not buy citations. Teams that add JSON-LD and see nothing change have usually mistaken a disambiguation tool for a content tool.

What earns its keep

  • Organization and WebSite. Name, URL, logo, sameAs. This is how a brand stops being three unrelated strings.
  • sameAs links. Point to the profiles that are genuinely yours, and keep them consistent; a stale profile is worse than none.
  • Article and BlogPosting with dates. Author, published, modified. Dates are read; wrong dates are read and distrusted.
  • FAQPage. Only where the questions and answers are visible on the page. Marking up hidden content is a violation and a waste.

What is usually overrated

Product markup on pages that are not products, breadcrumbs treated as an SEO ritual rather than navigation, and elaborate ontologies that describe a business nobody can verify. Structured data expresses facts; if the facts are thin, the markup is thin in a machine-readable way.

Test: remove all JSON-LD and reread the page. If it still says who you are, what you sell and what you claim, the markup was decoration. If it collapses, the markup was carrying the meaning, which is a fragile arrangement in the other direction.

Freshness and dates

Answers on volatile topics are assembled from pages whose currency can be judged. A visible last-updated date is that judgement made easy. A missing date is a reason to prefer another source, and a wrong date is a reason to distrust this one.

Two habits cause most date failures: bumping the modified timestamp on every deploy, which makes every page look freshly touched and therefore meaningless, and never touching it at all, which makes a five-year-old price look current.

  • Date only the pages whose facts can expire: prices, specifications, availability, regulation, rankings.
  • State the as-of month inside the sentence, not only in metadata, so a lifted passage carries its date.
  • Do not backdate or forward-date to look competitive. Both are detectable and both cost trust.

The crawl log as a diagnostic

Server logs answer questions no dashboard can: which agent requested which URL, what they got back, and how often. Three patterns are worth reading for.

PatternLikely causeFirst move
Retrieval agent never appears
Robots rule, firewall, or no discovery path
Fetch as that agent, then read robots.txt

The log also tells you what you have never looked at: which sections of the site are crawled and which are not, whether your newest pages were fetched within days or not at all, and whether a redirect chain is costing you entries.

How readiness failures masquerade as content failures

The reason this guide exists is the diagnosis problem. A brand that is absent gets told it needs better content, more content, or different content, and all three prescriptions are wrong when the page was never readable.

  • Absence on one surface and presence on another usually means one index, not one editor.
  • Absence on newly published pages while old pages still get cited usually means crawl discovery, not quality.
  • Presence without citation usually means the passage is there but not liftable, which is the one case that really is editorial.
  • Citation without absorption usually means the claim is not specific enough to be repeated.

Each of these has a different owner: platform, front end, editor, and writer respectively. Sending all four to the content team is how organisations end up rewriting pages that were never the problem.

The twelve checks

  1. Every page that matters returns 200 to the retrieval user agent, tested raw.
  2. robots.txt allows the retrieval agent on the paths you care about, not only the home page.
  3. Edge protection allowlists named agents rather than challenging all unfamiliar clients.
  4. Bing indexation is verified separately from Google indexation.
  5. Sitemap is fetched by crawlers, confirmed in the log, and lists canonical URLs only.
  6. Each page's canonical points to itself, with the trailing-slash form you actually serve.
  7. Unknown URLs return 404, not 200 with an apology page.
  8. Redirects are single-hop, and old paths are not left resolving to themselves.
  9. The document fetched without JavaScript still contains the passages you want quoted.
  10. Every section opens with a self-contained claim, and headings name their subject.
  11. Dates are visible, plausible, and limited to pages whose facts can expire.
  12. JSON-LD validates, matches the page, and describes entities you can corroborate elsewhere.

Twelve checks, one afternoon with a browser and a terminal, and they clear the denominator for everything else. Skip them and every later measurement is a measurement of your own plumbing.

Frequently asked questions

Is blocking GPTBot the same as opting out of AI answers?

No. Operators run separate agents for training and for retrieval, and blocking the training agent leaves retrieval intact in most documented setups. Check the current vendor documentation before deciding which one to block.

Do I need schema markup to be cited?

No. Citations come from the passage, not the markup. Schema helps a system resolve your entity and dates, which helps at the edges rather than the centre.

Is a JavaScript site hopeless?

No, but it is conditionally readable: it depends on a renderer running within a budget. Server-rendering the content routes removes the condition, which is why the fix is usually a front-end change rather than a content one.
